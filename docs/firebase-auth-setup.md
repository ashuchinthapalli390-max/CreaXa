# CreaXa: Firebase Authentication Setup & Configuration Guide

## 1. Overview

CreaXa uses **Firebase Authentication** as its primary identity provider, supporting three core sign-in methods for both creators and brand/agency accounts:
1. **Email and Password** (with email verification and password reset)
2. **Google OAuth** (using `GoogleAuthProvider`)
3. **Microsoft OAuth** (using `OAuthProvider('microsoft.com')` integrated with Microsoft Entra)

All methods authenticate client-side, obtain a signed Firebase ID Token, and synchronize session cookies (`__session` and `firebase_token`) with the Cloudflare Workers / Vinext backend.

### 2.2 Enabling Sign-In Providers
Navigate to **Build > Authentication > Sign-in method**:

1. **Email/Password**:
   - Enable **Email/Password**.
   - Optional: Enable **Email link (passwordless sign-in)** if desired.
2. **Google**:
   - Click **Add new provider > Google**.
   - Enable Google.
   - Choose your project support email and save.
3. **Microsoft (Microsoft Entra)**:
   - Click **Add new provider > Microsoft**.
   - Enable Microsoft.
   - Follow the steps in Section 3 below to obtain the **Application (client) ID** and **Client secret** from the Microsoft Entra portal.
   - Set the Redirect URI generated by Firebase (typically `https://creaxa-6e7bc.firebaseapp.com/__/auth/handler`).

### 2.3 Authorized Domains
Under **Authentication > Settings > Authorized domains**, add:
- `localhost`
- `127.0.0.1`
- `creaxa-6e7bc.firebaseapp.com`
- `creaxa-6e7bc.web.app`
- Your production domain (e.g. `creaxa.ai`, `*.workers.dev`)

## 3. Microsoft Entra (Azure AD) App Registration

To enable Microsoft single sign-on:
1. Sign in to the [Microsoft Entra admin center](https://entra.microsoft.com/) or Azure Portal.
2. Navigate to **Identity > Applications > App registrations > New registration**.
3. **Name**: `CreaXa Marketplace`
4. **Supported account types**:
   - Select: *Accounts in any organizational directory (Any Microsoft Entra ID tenant - Multitenant) and personal Microsoft accounts (e.g. Skype, Xbox)*.
5. **Redirect URI**:
   - Platform: `Web`
   - URL: `https://creaxa-6e7bc.firebaseapp.com/__/auth/handler`
6. Register the application and record:
   - **Application (client) ID**
7. Navigate to **Certificates & secrets > Client secrets > New client secret**:
   - Add a description (e.g. `Firebase Auth Secret`).
   - Copy the secret **Value**.
8. Return to Firebase Console Microsoft Provider settings:
   - Enter Application (client) ID and Client secret.
   - Save changes.

## 4. Supabase Third-Party Firebase Auth Integration

To allow Supabase PostgreSQL to verify Firebase ID tokens directly:
1. Open the [Supabase Dashboard](https://supabase.com/dashboard) for your project.
2. Navigate to **Authentication > Providers > Third-Party Auth (or Custom JWT)**.
3. Add a new JWT Provider:
   - **Issuer**: `https://securetoken.google.com/creaxa-6e7bc`
   - **Audience**: `creaxa-6e7bc`
   - **JWKS URL**: `https://www.googleapis.com/service_accounts/v1/jwk/securetoken@system.gserviceaccount.com`
4. In Firebase custom claims, new users receive the claim `role: "authenticated"` so that Supabase PostgreSQL Row Level Security evaluates `auth.role() = 'authenticated'`.
